# 나만의 일본어 공부 사이트 기획서

Oct 21, 2026 · @수영

## 개요

내가 직접 등록한 단어·문법·답변·작문만으로 공부하는 1인용 일본어 학습 웹사이트를 만든다. 핵심은 **단어 카드 테스트**이고, 문법 노트·회화/면접 대비·작문 연습이 같은 데이터를 공유한다.

- **사용자**: 나 1명.
- **사용 환경**: PC와 휴대폰을 번갈아 쓴다. 두 기기는 처음부터 같은 데이터를 동기화한다. 휴대폰은 스와이프, PC는 키보드 방향키로 같은 조작을 한다.
- **AI 비용**: 추가 결제 없이, Gemini API 무료 등급으로 AI 기능(발음 평가 포함)을 쓴다(‘AI·음성·동기화 연동 방식’ 참고).
- **참고 화면**: `일본어 학습` 폴더의 스크린샷 7장(단어 카드, 클릭 시 공개, 한자 정보, 한자별 단어 모음, 리스트 형식). 후리가나 위 악센트 표시선은 넣지 않는다.

설계 원칙은 세 가지다.

1. **가렸다가 확인하기**: 원문만 먼저 보이고, 클릭하면 후리가나(위)와 뜻(아래)이 열리고, 다시 클릭하면 닫힌다.
2. **모든 것은 한자로 이어진다**: 단어 속 한자를 누르면 한자 정보, 한자를 다시 누르면 그 한자가 들어간 내 단어 모음.
3. **보기 형식은 내가 고른다**: 단어 테스트를 뺀 모든 목록은 리스트형/카드형 중 선택.
4. **모든 것은 기기 간에 이어진다**: 내가 만든 데이터, AI 분석 결과, 녹음·사진, 진행 중인 테스트·면접·작문, 설정까지 PC와 휴대폰에서 같게 보인다. 한 기기에서 시작한 일을 다른 기기에서 이어서 할 수 있다(데이터 구조 > 기기 간 동기화).

## 정보 구조

메뉴는 단어장·단어 테스트·문법 노트·회화/면접·작문 5개이고, 검색과 설정은 모든 화면 상단에 둔다.

> (그림: 메뉴 구성 · 단어 학습 4화면, 표현 학습 3메뉴 — 원본 기획서에서 볼 수 있음)

단어장 → 한자 정보 창 → 한자별 단어 모음으로 파고들고, 단어장·한자별 모음·검색 결과 어느 목록에서든 그 목록 그대로 단어 테스트를 시작한다.

## 단어장

단어장은 내가 등록한 단어를 **원문 → 후리가나(히라가나) → 뜻** 순서로 보여주고, 여기서 바로 단어 테스트를 시작한다.

### 단어 등록

| 항목 | 필수 | 예시 | 비고 |
| --- | --- | --- | --- |
| 원문 | 필수 | 納める | 한자·가나 혼용 가능 |
| 후리가나 | 필수 | おさめる | 히라가나로 저장. 가타카나로 입력해도 히라가나로 변환 |
| 뜻 | 필수 | 납부하다, 거두다 | 여러 뜻은 쉼표로 구분 |
| JLPT 레벨 | 선택 | N3 | N5\~N1, 기타. 카드 왼쪽 위 배지로 표시 |
| 품사 | 선택 | 2그룹 동사 | 카드 오른쪽 아래 태그 |
| 예문 + 해석 | 선택 | 税金を納める。 / 세금을 납부하다. | 예문 속 해당 단어는 강조색 |
| 태그 | 선택 | 면접, 뉴스 | 테스트 범위 지정에 사용 |
| 한글 발음 | 자동 | 오사메루 | 후리가나에서 자동 생성, **화면에 표시하지 않음**(검색 전용) |
| 포함 한자 | 자동 | 納 | 원문에서 한자만 추출해 한자 정보와 연결 |

등록은 한 개씩 입력과 CSV/엑셀 일괄 등록 두 가지를 둔다. 원문을 입력하면 AI(빠른 모델)가 후리가나·뜻·레벨·예문 초안을 채우고, 나는 확인·수정만 한다.

### 보기 화면

- **리스트형 (기본: 모두 표시)**: 한 줄에 단어 하나. 왼쪽부터 레벨 배지 · 원문 · 후리가나 · 뜻, 오른쪽 끝에 듣기·즐겨찾기·북마크. (참고: `리스트 형식 예시` 스크린샷)
- **카드형 (기본: 가리기)**: 카드가 세로로 나열되고, 처음에는 원문과 예문 원문만 보인다. 카드를 누를 때마다 3단계로 바뀐다. (참고: `단어장 클릭시 후리가나와 뜻 공개` 스크린샷)
  1. 1번 누름 → 원문 **위에 후리가나** 표시(예문에도 후리가나)
  2. 2번 누름 → 원문 **아래에 뜻** 표시(예문 해석도 함께)
  3. 3번 누름 → 모두 숨김, 처음 상태로
- **가리기 기본값**: 리스트형은 모두 표시, 카드형은 가리기. 설정에서 형식별로 바꿀 수 있고, 리스트형에서 가리기를 켜면 같은 3단계로 동작한다.
- **듣기**: 단어와 예문 옆에 각각 스피커 버튼을 두고, 누르면 일본어 음성으로 읽는다. 가려진 상태에서도 들을 수 있다.
- **상단 바**: 뒤로가기, 단어 수, 셔플, 검색. **하단**: 보기 형식 전환 버튼(왼쪽), ‘테스트 시작’ 버튼(오른쪽).
- 정렬: 등록일(기본) · 레벨 · あいうえお순 · ‘모름’ 횟수 많은 순. 필터: 레벨, 태그, 북마크.

### 클릭 영역

한 항목 안에서 누른 위치에 따라 동작을 나눈다. 가리기 클릭과 한자 클릭이 충돌하지 않게 하기 위해서다.

| 누르는 곳 | 동작 |
| --- | --- |
| 원문 속 **한자 한 글자** | 화면 아래에 한자 정보 창이 올라옴 |
| 원문의 가나 부분·빈 영역 | 가려져 있을 때: 후리가나 → 뜻 → 모두 숨김 순서로 전환 |
| 복사 아이콘 | 원문(또는 예문) 클립보드 복사 |
| 길게 누르기 | 단어 수정·삭제 메뉴 |
| 스피커 아이콘 | 단어 또는 예문을 일본어 음성으로 듣기(기기 내장 음성, 무료) |

### 한자 정보 창

한자를 누르면 화면 아래에서 시트가 올라온다(참고: `단어장 한자 클릭시 한자 정보`). 바깥을 누르거나 아래로 끌면 닫힌다. 모든 정보는 **일본 한자 기준**이다.

- **자체**: 일본 상용한자표의 글자꼴(継). 한국·대만에서 쓰는 정자(繼)는 ‘이체자’ 칸에만 작게 표시한다.
- **획수·획순**: 일본식 기준. 정자의 획수(繼 20획)가 아니라 継 13획으로 센다.
- **음독·훈독**: 일본 상용한자표의 음훈을 먼저 보여주고, 그 밖의 읽기(예: 継의 まま-)는 ‘표외’ 표시를 붙여 회색으로 둔다.
- **한국어 훈음(이을 계)**: 한국 학습자용 이름표다. 네이버 일본어사전이나 일본어 한자 공부방(nihongokanji.com)을 기준으로 내가 확인해 저장한다. 창에는 두 사이트의 해당 한자 링크를 항상 둔다(아래 ‘사이트 링크 버튼’).

| 항목 | 예시(継) | 가져오는 곳 |
| --- | --- | --- |
| 한자 + 한국어 훈음 | 継 이을 계 | 내가 확인해 입력 (네이버·nihongokanji 링크 제공) |
| 이체자 | 繼 | KANJIDIC2 |
| 부수 | 糸 (실 사) | KANJIDIC2 + 부수 훈음표 |
| 훈독 | つぐ (표외: まま-) | KANJIDIC2, 상용한자표와 대조해 표외 표시 |
| 음독 | ケイ | KANJIDIC2 |
| 획수 | 13 | KANJIDIC2 |
| 획순 | 번호가 붙은 획순 그림 + 한 획씩 그려지는 애니메이션 | KanjiVG (일본 한자 획순 SVG) |
| 구성 원리 | ‘일본어 한자 공부방’·‘네이버 일본어사전’ 링크 버튼 + 내 메모 | 두 사이트 링크, 메모는 내가 작성 |

### 획순 그림

첨부하신 캡처처럼 큰 한자 위 각 획의 시작점에 번호(1\~13)를 붙여 보여준다. ▶ 버튼을 누르면 1획부터 차례로 그려지고, 번호를 누르면 그 획만 강조된다. 그림은 nihongokanji.com의 이미지를 쓰지 않고 [KanjiVG](https://kanjivg.tagaini.net/) 데이터로 직접 그린다. KanjiVG는 일본어 한자의 획·획 방향·획순을 담은 공개 SVG이고, CC BY-SA 3.0이라 출처(© Ulrich Apel)를 표시하면 쓸 수 있다.

### 구성 원리(한자 모양 해설)

nihongokanji.com의 해설은 가져오지 않고 **링크로 연결**한다. 사이트의 [저작권 및 이용 안내](https://nihongokanji.com/copyright/)가 크롤링·스크래핑, 해설과 이미지를 다른 서버나 저장소로 옮기는 것(개인 앱 포함)을 사전 허락 사항으로 정해 두었기 때문이다. 링크는 자유롭게 걸 수 있고, 직접 캡처해 내 기기에 저장하는 것도 개인 학습용으로 허용된다.

- **사이트 링크 버튼 2개**: 창 아래에 항상 두고, 누르면 새 창으로 연다. 운영자 허락은 따로 받지 않고 링크만 건다.
  - **일본어 한자 공부방**: 한자 페이지 주소가 글 번호라 한자만으로는 만들 수 없다(継 = [nihongokanji.com/1127](https://nihongokanji.com/1127/), 사이트 번호 1115). 저장된 주소가 없으면 ‘site:nihongokanji.com 「継」’ 구글 검색을 열고, 찾은 주소를 붙여 넣으면 그 한자에 저장돼 PC·휴대폰 모두에서 바로 열린다.
  - **네이버 일본어사전**: 한자마다 한자 검색 링크를 자동으로 만든다(예: `https://ja.dict.naver.com/#/search?query=継&range=letter`). 한자 항목 페이지 주소를 붙여 넣어 두면 다음부터는 그 항목으로 바로 연다. 네이버는 제 쪽에서 접속이 막혀 있어, 이 주소가 한자 탭을 바로 여는지는 개발할 때 확인한다.
- **내 메모**: 해설을 읽고 내 말로 요약한 구성(예: 糸 실 + 𠃊+米 실뭉치 → 실이 이어짐)을 적는 칸. 부품 한자를 누르면 그 한자의 정보 창으로 바뀐다.

### 한자 정보 출처 비교 (継 기준)

| 항목 | KANJIDIC2 ([jisho.org](https://jisho.org/search/%E7%B6%99%20%23kanji) 표시) | nihongokanji.com ([継 페이지](https://nihongokanji.com/1127/)) | 네이버 일본어사전 |
| --- | --- | --- | --- |
| 자체 | 継 (이체자 繼) | 継 | 링크로 확인 |
| 한국어 훈음 | 없음 (한국 음 gye만) | 이을 계 | 링크로 확인 |
| 음독 | ケイ | ケイ | 링크로 확인 |
| 훈독 | つぐ, まま- | つ(ぐ) | 링크로 확인 |
| 획수 | 13 | 13 (획순 그림 번호 1\~13) | 링크로 확인 |
| 부수 | 糸 | 따로 적지 않음(糸를 ‘실’로 설명) | 링크로 확인 |
| 구성 | 부품 목록 ｜ 小 幺 米 糸 (검색용 분해) | 糸 + 𠃊(ㄴ 모양) + 米, 실뭉치에서 실이 이어짐 | 링크로 확인 |
| JLPT | N1 | N1 | — |
| 출처 공개 | 편찬 이력·기여자 공개 | 출처 표기 없음 | — |

- **KANJIDIC2 — 기본 데이터로 믿을 만하다.** 1991년부터 EDRDG(Jim Breen)가 관리해 왔고 데이터마다 출처를 밝힌다. 부수는 JIS漢字字典, 학년 배당은 일본 문부성 기준이고, 한국 음은 Charles Muller 박사가 제공했다([KANJIDIC Project](https://www.edrdg.org/wiki/KANJIDIC_Project.html)). 다만 획수는 한 가지 기준을 엄격히 따르지 않고 Halpern 사전에 가깝다고 밝힌다. まま- 같은 상용한자표 밖 읽기도 섞여 있고, 한국어 훈은 없다.
- **nihongokanji.com — 한국어 훈음·해설에 유용하다.** 상용한자 2,136자를 일본 기준으로 다루고, KANJIDIC2와 음독·훈독·획수가 일치한다. 단 출처를 밝히지 않고, ‘한자 모양 해설’은 운영자가 ‘한 자 한 자 직접 고안해 쓴 창작물’이라고 적는다. 학술적 자원(字源)이라기보다 암기를 돕는 풀이로 보는 것이 맞다.
- **네이버 일본어사전 — 한국어 훈음의 기준으로 쓴다.** 출처 표기는 직접 확인해 문제가 없었다. 제 쪽에서는 접속이 막혀 값을 표에 채우지 못했으므로, 훈음은 링크로 열어 확인한 뒤 입력한다.
- **공식 기준은 문화청 「常用漢字表」(2010)이다.** 일본 한자의 자체와 상용 음훈은 이 표가 정한다([문화청 참고](https://www.bunka.go.jp/seisaku/kokugo_nihongo/kokugo_shisaku/joyokanjihyo_sakuin/index.html)). 앱의 ‘표외’ 표시는 이 표와 대조해 만든다.

창 안의 **큰 한자를 다시 누르면** ‘한자별 단어 모음’ 화면으로 이동한다. (획순 그림은 큰 한자 아래에 따로 두어, 누르는 동작이 겹치지 않게 한다.)

### 한자별 단어 모음

내가 등록한 단어 중 그 한자가 들어간 것만 모아 보여준다(継 → 継ぐ, 受け継ぐ, 継続, 継続的 …). 단어장과 같은 리스트형/카드형 전환, 같은 클릭 규칙을 쓴다. 상단에 ‘이 단어들로 테스트’ 버튼을 둔다. (참고: `한자 정보에서 다시 한자 클릭 시` 스크린샷)

## 단어장 테스트

모든 단어를 오른쪽(아는 단어)으로 넘길 때까지, 왼쪽(모르는 단어)으로 넘긴 단어가 랜덤 순서로 다시 나오는 카드 테스트다. (참고: `단어장 카드`, `단어장 카드 클릭 시`, `단어장 사용법` 스크린샷)

> (그림: 단어 테스트 반복 흐름 · 판 단위 반복 — 원본 기획서에서 볼 수 있음)

한 판을 끝까지 넘긴 뒤 왼쪽으로 넘긴 단어만 다시 섞어 다음 판을 만들고, 더미가 빌 때 테스트가 끝난다.

### 카드 상태

| 상태 | 보이는 것 | 다음 동작 |
| --- | --- | --- |
| 숨김(처음) | 원문만 크게 (折) | 카드 클릭 → 공개 |
| 공개 | 위: 후리가나 (おる) / 가운데: 원문 / 아래: 뜻 (꺾다) | 카드 클릭 → 다시 숨김 |

공개/숨김은 몇 번이든 반복할 수 있고, 스와이프는 어느 상태에서나 가능하다. 한자 정보는 카드 클릭과 겹치지 않도록 카드 오른쪽 아래 ‘한자’ 버튼으로만 연다.

### 조작

| 조작 | 모바일 | PC | 결과 |
| --- | --- | --- | --- |
| 공개/숨김 | 카드 탭 | Space | 상태 전환 |
| 아는 단어 | 오른쪽 스와이프 또는 → 버튼 | → 키 | 완료 처리, 더 안 나옴 |
| 모르는 단어 | 왼쪽 스와이프 또는 ← 버튼 | ← 키 | 다시 보기 더미에 넣음 |
| 되돌리기 | 하단 ↶ 버튼 | Z | 직전 스와이프 취소 |

스와이프 중에는 카드가 손가락을 따라 기울고, 오른쪽은 초록·왼쪽은 빨강 테두리로 표시한다. 화면 폭의 30% 이상 끌어야 넘어가고, 그보다 짧으면 제자리로 돌아온다.

### 반복 규칙

1. 테스트 범위의 단어를 섞어 첫 번째 판을 만든다.
2. 판을 끝까지 넘기면, 왼쪽으로 넘긴 단어만 다시 랜덤으로 섞어 다음 판을 만든다. 직전 판의 마지막 단어가 바로 다시 나오지 않게 한다.
3. 왼쪽 더미가 빌 때까지 2를 반복한다.
4. 완료 화면: 총 단어 수, 걸린 시간, 판 수, 여러 번 모른다고 한 단어 목록(바로 북마크 가능).

선택 설정으로 ‘연속 정답 횟수’(스크린샷의 x1)를 둔다. x2로 두면 모르는 단어로 한 번이라도 넘긴 단어는 연속 2번 오른쪽으로 넘겨야 완료된다. 기본값은 x1(요청하신 규칙 그대로).

### 테스트 화면 구성

- 상단: 나가기, 진행도(아는 단어 수 / 전체, 예: 12/25), 경과 시간, 현재 판 번호.
- 카드: 왼쪽 위 레벨 배지, 오른쪽 복사·듣기 아이콘, 오른쪽 아래 ‘한자’ 버튼. 테스트 카드는 단어장과 달리 1번 누르면 후리가나와 뜻이 함께 열린다.
- 하단: ← 모름 / → 아름 버튼, 되돌리기.
- 첫 사용 시 사용법 오버레이 1회(‘다시 보지 않기’ 체크).
- 테스트 중간에 나가도 진행 상황을 저장해 이어서 할 수 있게 한다.

### 테스트 범위

단어장 화면에서 지금 보이는 목록(필터·검색 결과 포함)이 그대로 테스트 범위가 된다. 예: ‘N2 + 면접 태그’, ‘북마크만’, ‘継가 들어간 단어’. 개수 제한(10/25/50/전체)도 고를 수 있다.

## 검색

검색창 하나로 원문·후리가나·뜻·한글 발음을 모두 찾는다. 納める는 아래 어떤 검색어로도 나와야 한다.

| 검색어 | 입력 종류 | 매칭되는 곳 |
| --- | --- | --- |
| 納 / 納め | 한자 포함 | 원문 |
| おさ / おさめる | 히라가나 | 후리가나 |
| オサメル | 가타카나 | 히라가나로 바꿔 후리가나 |
| 오사메루 / 오사메 | 한글 | 한글 발음 키(보이지 않는 값) |
| 납부 / 거두다 | 한글 | 뜻 |
| 들일 납 | 한글 | 한자 훈음 → 納이 들어간 단어 |
| osameru (선택) | 로마자 | 가나로 바꿔 후리가나 |

### 한글 발음 키 만들기

단어를 저장할 때 후리가나를 가나→한글 표로 바꿔 한글 발음 키를 만든다(おさめる → 오사메루). 이 값은 검색에만 쓰고 단어장·카드 어디에도 표시하지 않는다. 후리가나를 고치면 키도 자동으로 다시 만든다.

사람마다 일본어를 한글로 적는 방식이 다르므로, 비교 전에 검색어와 키를 **같은 규칙으로 정규화**한다.

| 흔들리는 지점 | 같은 것으로 보는 표기 | 예 |
| --- | --- | --- |
| 예사소리·거센소리·된소리 | ㄱ·ㅋ·ㄲ, ㄷ·ㅌ·ㄸ, ㅂ·ㅍ·ㅃ, ㅈ·ㅊ·ㅉ, ㅅ·ㅆ | 카미 = 가미, 토모다치 = 도모다찌 |
| つ | 츠 = 쓰 = 쯔 | 츠기 = 쓰기 |
| 요음(しゃ·じゃ·ちゃ 등) | 샤 = 사, 쟈 = 자, 챠 = 차 | 샤신 = 사신 (しゃしん) |
| 장음(おう·えい·ー) | 길게 적거나 생략 | 토오쿄오 = 도쿄, 센세이 = 센세 |
| ん 받침 | ㄴ·ㅁ·ㅇ 받침, ‘응’ | 신분 = 심붕 = 신붕 |
| っ 받침 | ㅅ 받침, 생략, 다음 자음 된소리 | 킷테 = 키테 = 키떼 |
| を / へ / は | 오 / 에 / 와(조사) | — |
| 띄어쓰기 | 무시 | — |

장음은 키를 두 개(긴 형태, 줄인 형태) 만들어 둘 중 하나에 맞으면 찾은 것으로 한다. 요음·つ처럼 두 글자가 한 소리인 경우는 자음 통일보다 먼저 처리해야 つ(쓰)와 す(스)가 섞이지 않는다.

### 검색 동작

- **입력 종류 자동 판별**: 한자가 있으면 원문, 가나만 있으면 후리가나+원문, 한글이면 뜻과 한글 발음 키를 동시에 찾는다.
- **부분 일치**: 어느 위치든 포함되면 찾는다(오사메 → 오사메루).
- **결과 순서**: 완전 일치 → 앞부분 일치 → 중간 포함. 한글 검색은 ‘발음 일치’와 ‘뜻 일치’를 나눠 보여준다.
- **즉시 검색**: 글자를 칠 때마다 결과 갱신(일본어 IME 변환 중에는 기다렸다가 확정 후 검색).
- **검색 범위 탭**: 전체 · 단어 · 한자 · 문법 · 회화/면접 · 작문.
- 결과는 리스트형/카드형으로 보이며, 결과 목록으로 바로 단어 테스트를 시작할 수 있다.
- 최근 검색어 10개를 검색창 아래에 보여준다.

## 문법 노트

공부한 문법을 문형 단위로 정리하고, 예문 속 단어는 단어장과 연결한다.

| 항목 | 예시 |
| --- | --- |
| 문형 | 〜わけにはいかない |
| 접속 | 동사 사전형 / 동사 ない형 + わけにはいかない |
| 뜻 | \~할 수는 없다(사정상) |
| 설명 | 내 말로 적는 노트, 자유 서식 |
| 예문 + 해석 | 여러 개. 예문 속 문형 부분은 강조색 |
| JLPT 레벨 / 태그 | N2 / 의무·금지 |
| 비슷한 문법 | 〜ざるを得ない 같은 다른 문법 노트로 연결, 차이점 메모 |

- 목록은 리스트형(문형 · 뜻 · 레벨)과 카드형(문형 · 접속 · 뜻 · 대표 예문)을 전환한다.
- 상세 화면에서 예문 속 한자를 누르면 단어장과 같은 한자 정보 창이 뜨고, 아직 등록 안 한 단어는 드래그해서 ‘단어장에 추가’할 수 있다.
- 복습(선택): 예문의 문형 부분을 빈칸으로 가린 카드를 단어 테스트와 같은 좌우 스와이프 방식으로 넘긴다.

## 회화·면접 대비

AI 면접관이 내가 정한 상황에 맞는 질문을 **음성으로만** 내고, 내가 말로 답하면 질문과 답을 원문·해석으로 보여주고 교정한다. 질문을 이어갈지는 매번 내가 고르고, 끝난 면접은 통째로 목록 하나로 저장된다.

> (그림: AI 면접 세션 흐름 · 질문마다 반복 — 원본 기획서에서 볼 수 있음)

분석 결과를 본 뒤 다음 질문, 같은 질문 다시 답하기, 면접 종료 중 하나를 고르고, 종료하면 그때까지의 문답이 한 번에 저장된다.

### 문화복장학원 복장과 입시 맞춤

2027년도 유학생 입시는 일본어 필기(어휘·독해·문법)와 약 400자 작문(합쳐 70분), 그리고 **집단 면접**이다. 문제는 모두 일본어로 나오고 일본어로 답해야 한다([유학생 입시 안내](http://www.bunka-fc.ac.jp/prospectivestudent/international-2)). 복장과는 2년 과정으로, 1학년에 평면 제도와 봉제, 2학년에 입체 재단을 배운다([복장과 소개](https://www.bunka-fc.ac.jp/course/fukusyokusenmon-katei/fukusou-ka/)). 면접 메뉴의 기본 프리셋은 이 조건으로 만든다.

- **기본 프리셋**: 文化服装学院 服装科 留学生入試, 2인 1조 그룹 면접(약 10분), 신입 유학생, 정중체·경어.
- **이력 요약(프리셋에 저장)**: 한국에서 패션디자인 학사 취득(학점은행제), 패션 브랜드 인턴 6개월, 아이돌 무대의상 제작 경험. 이름·학교명·연락처는 넣지 않는다.
- **2인 그룹 면접 모드**: 실제처럼 지원자 2명이 한 조로 약 10분 동안 면접을 본다. AI가 면접관과 다른 지원자 1명을 맡는다. 같은 질문에 다른 지원자가 먼저 답하는 걸 듣고 내 차례에 답한다. 앞 사람과 겹치지 않게 답하는 연습이 된다. 1:1 모드도 고를 수 있다.
- **답변 목표 시간**: 설정에서 정한다(기본 45초). 10분을 두 사람이 나눠 답하므로, 한 답변이 1분을 넘지 않는 것을 목표로 한다. 넘기면 분석에서 ‘길이’ 지적을 받는다.

면접은 두 가지 모드로 고른다.

| 모드 | 진행 | 분석 |
| --- | --- | --- |
| 연습 | 질문 하나씩, 이어갈지 매번 선택 | 질문마다 바로 분석·교정 |
| 실전(10분) | 10분 타이머가 돌고 중간에 멈추지 않음. 시간이 다 되면 면접관이 마무리 인사를 하고 끝남 | 끝난 뒤 문답 전체를 한 번에 분석해 저장 |

실전 모드는 들어가기 → 인사 → 질문 → 마무리 인사까지 한 번에 연습하는 용도다. 한 조에서 내가 먼저 답할지 나중에 답할지는 질문마다 섞는다.

AI는 아래 범주에서 질문을 고르고 내 이력에 맞게 바꾼다. 실제 기출 질문이 아니라 예상 질문이다.

| 범주 | 예상 질문 방향 |
| --- | --- |
| 자기소개 | 1분 자기소개 |
| 지원 동기 | 왜 문화복장학원인지, 왜 복장과인지, 왜 일본인지 |
| 학력 | 학점은행제로 학사를 받은 과정, 학사가 있는데 다시 전문학교에 가려는 이유 |
| 경험 | 브랜드 인턴에서 맡은 일과 배운 점, 무대의상 제작에서 어려웠던 점과 해결 |
| 기술·관심 | 자신 있는 기술, 복장과에서 배우고 싶은 것(평면 제도·입체 재단 등), 좋아하는 디자이너·브랜드 |
| 졸업 후 | 진로, 전공과 진학 여부, 일본 취업 또는 귀국 |
| 일본어·생활 | 일본어 공부 방법, 유학 생활 계획 |

학점은행제처럼 일본에 없는 제도는 일본어로 짧게 설명하는 연습이 필요하다. 그래서 학력 질문에는 꼬리 질문을 한 번 이상 꼭 붙이고, 처음 나올 때 다듬은 답변에 설명 표현을 포함한다.

### 면접 진행

1. **상황 설정**: 학교·학과 또는 회사·직무, 면접 형식(집단/1:1, 대면·온라인), 내 이력 요약(선택). 기본값은 위의 문화복장학원 프리셋이다. 자주 쓰는 상황은 프리셋으로 저장한다.
2. **질문 선정**: AI가 상황과 지금까지의 문답을 보고 다음 질문 1개를 고른다. 한 질문은 다시 내지 않고, 앞 답변에 대한 꼬리 질문도 섞는다.
3. **음성으로만 질문**: 화면에는 질문 글자를 보여주지 않는다. ‘다시 듣기’(횟수 기록)와 ‘느리게 듣기’(0.8배)만 있다.
4. **음성 답변**: 마이크 버튼을 누르고 말하면 답변이 녹음된다. 녹음을 Gemini에 보내 글자로 옮기고 발음을 평가한다. 답변 시간을 재고, 옮겨 적은 글이 틀리면 고칠 수 있지만 발음 평가는 원래 녹음 기준이다.
5. **분석 결과**: 아래 표의 내용을 한 화면에 보여준다.
6. **이어가기 선택**: \[다음 질문\] · \[같은 질문 다시 답하기\] · \[면접 종료\]. 다음 질문을 고르면 2번부터 반복한다.
7. **세션 저장**: 종료하면 상황 설정과 모든 문답·교정이 ‘면접 기록’ 목록의 한 항목으로 등록된다. 저장 전에 제목을 붙이거나 일부 문답을 빼고 저장할 수 있다.

| 분석 화면 | 내용 |
| --- | --- |
| 질문 | 일본어 원문 + 한글 해석 (이때 처음 글자로 공개) |
| 내 답변 | 녹음에서 옮긴 일본어 원문 + 한글 해석, 내 녹음 다시 듣기 |
| 발음 | 장음·촉음(っ)·ん·탁음/청음이 다르게 들린 단어, 억양·속도·말끝 흐림. ‘모범 발음 / 내 녹음 / AI가 들은 대로’ 버튼으로 바로 비교해 듣고, 지적된 단어마다 ‘올바른 발음 / 들린 소리’를 들어 본다 |
| 교정 | 틀린 부분 → 고친 표현, 이유(문법·어휘·경어·면접 표현). 내 답변 원문에 밑줄로 위치 표시 |
| 다듬은 답변 | 내 내용을 살린 모범 답변 원문 + 해석, 듣기 버튼 |
| 한줄 평가 | 질문 의도에 맞았는지, 경어, 결론 먼저 말했는지, 길이, 집단 면접에서는 앞 사람 답과 겹쳤는지 |

발음 평가는 Gemini가 녹음을 직접 듣고 한다. 점수보다 ‘어느 단어가 어떻게 들렸는지’를 중심으로 보여주고, AI 평가는 참고용이므로 같은 지적이 여러 번 나오는 단어를 모아 ‘발음 주의 단어’로 복습한다.

### 회화 연습

면접과 같은 흐름이고, 상황만 일상 장면(가게, 병원, 직장 동료와 잡담 등)으로 바꾼다. AI는 점원·동료 같은 상대역으로 말을 건다. 말투(반말·정중체·경어)도 상황 설정에서 고른다.

### 기록 목록

- **리스트형**: 날짜 · 제목(상황) · 질문 수 · 교정 수. **카드형**: 세션별 카드, 펼치면 질문별 문답.
- **복습 모드**: 저장한 세션의 질문을 다시 음성으로 듣고 답한 뒤, 다듬은 답변과 비교한다. 모르는 질문은 단어 테스트처럼 다시 나온다.
- 교정된 표현은 탭 한 번으로 단어장·문법 노트로 보낼 수 있다.

## 작문 연습

내가 정한 카테고리나 상황에 맞춰 AI가 일본어 질문을 내고, 종이나 원고지에 손으로 쓴 답을 사진으로 올리면 분석한다. 잘못 쓴 한자는 사진 위에 표시하고, 아래에 교정을 보여준다.

### 작문 진행

1. **설정**: 카테고리(자기소개, 지원동기, 일상, 의견문, JLPT형 등) 또는 상황 직접 입력, 목표 글자 수(200/400/800자), 쓰는 종이(원고지 가로쓰기 / 원고지 세로쓰기 / 일반 종이). 기본값은 400자 원고지 가로쓰기다. ‘입시 연습’을 켜면 문화복장학원 입시처럼 약 400자를 제한 시간 안에 쓰도록 타이머가 돈다(시간은 내가 정함, 실제 시험은 필기와 작문을 합쳐 70분).
2. **AI 질문**: 화면에 **일본어 원문으로만** 표시한다. 해석은 분석 후에 공개한다. 마음에 안 들면 ‘다른 질문’으로 바꾼다.
3. **손으로 쓰고 사진 올리기**: 휴대폰에서는 카메라로 바로 찍고, PC에서는 파일을 고른다. 여러 장을 올릴 수 있고, 올리기 전에 자르기·회전을 한다.
4. **글자 읽기 확인**: AI가 사진 속 글을 텍스트로 옮긴 결과를 먼저 보여준다. 잘못 읽은 곳만 고치고 ‘분석’을 누른다. (내가 잘못 쓴 한자는 고치지 않고 그대로 둔다.)
5. **분석 결과**: 아래 표의 내용을 순서대로 보여준다.
6. **저장**: 사진, 읽은 글, 분석 결과가 작문 기록 한 항목이 된다. 틀린 한자·표현은 단어장·문법 노트로 보낼 수 있다.

| 분석 화면 | 내용 |
| --- | --- |
| 사진 + 한자 오류 표시 | 올린 사진 위 잘못 쓴 한자에 빨간 테두리와 번호. 누르면 확대 |
| 한자 오류 목록 | 같은 번호로 ‘쓴 글자 → 바른 글자’, 이유(획 빠짐·비슷한 한자 혼동·오쿠리가나 오류). 바른 한자는 한자 정보 창과 연결 |
| 질문 | 일본어 원문 + 한글 해석 |
| 내 답 | 사진에서 읽은 일본어 원문 + 한글 해석 |
| 문장 교정 | 틀린 부분 → 고친 표현, 이유(문법·어휘·문체 통일) |
| 원고지 표기 | 원고지로 올린 경우만. 틀린 규칙과 위치(몇 행 몇 칸), 사진에도 노란 테두리로 표시 |
| 교정본 | 고친 글 전체 원문 + 해석, 듣기 버튼 |

### 원고지 표기법 검사 항목

| 규칙 | 내용 |
| --- | --- |
| 제목 | 첫 행, 위에서 2\~3칸 띄우고 쓴다 |
| 이름 | 다음 행 아래쪽에, 끝 칸을 1칸 비우고 쓴다. 성과 이름 사이 1칸 |
| 문단 시작 | 첫 칸을 1칸 비우고 시작한다 |
| 구두점 。、 | 한 칸을 차지한다. 행의 첫 칸에 오면 안 되고, 앞 행 마지막 칸에 글자와 함께 넣는다 |
| 닫는 괄호 」 | 구두점과 같이 행 첫 칸에 오면 안 된다. 。와 」가 이어지면 한 칸에 함께 |
| 대화문 「」 | 새 행 첫 칸부터 쓴다 |
| 작은 글자 っゃゅょ | 한 칸을 차지한다. 세로쓰기는 칸의 오른쪽 위, 가로쓰기는 왼쪽 아래 |
| 장음 ー | 세로쓰기에서는 세로로 쓴다 |
| 숫자 | 세로쓰기는 한자 숫자(二〇二六), 가로쓰기는 아라비아 숫자 2자를 한 칸에 |
| …… / ―― | 2칸에 걸쳐 쓴다 |

기본 검사는 가로쓰기 기준이고, 세로쓰기 전용 항목(장음 세로 표기, 한자 숫자)은 세로쓰기를 고를 때만 검사한다. 학교·시험마다 제목·이름 위치 등 세부 규칙이 다를 수 있어, 항목별로 검사를 켜고 끌 수 있게 한다.

### 사진 분석의 한계

- 400자 원고지 한 장을 통째로 찍으면 글씨가 작아 잘못 읽힐 수 있어, 페이지를 2\~4조각으로 나눠 한 번에 보낸다.
- 원고지는 칸 번호(행·열)로 위치를 받아 사진 위에 정확히 표시할 수 있다. 일반 종이는 대략적인 위치여서 표시가 조금 어긋날 수 있다.
- 흘림체나 흐린 사진은 읽기 오류가 늘어, 4번(글자 읽기 확인) 단계를 건너뛸 수 없게 한다.

작문 목록은 날짜순이며, 리스트형(날짜 · 질문 첫 줄 · 한자 오류 수 · 교정 수)과 카드형(사진 썸네일 + 교정본 미리보기)을 전환한다. 자주 틀리는 한자와 문법은 따로 모아 보여주고, 바로 단어 테스트로 돌릴 수 있다.

## AI·음성·동기화 연동 방식

발음을 평가하려면 AI가 녹음을 직접 들어야 하므로, AI는 **Google Gemini API 무료 등급** 하나로 통일한다. Claude 아티팩트 페이지는 외부 서버로 요청을 보낼 수 없어 Gemini를 부를 수 없다. 그래서 사이트는 무료 웹 호스팅에 따로 올리고, 모든 구성을 무료 등급 안에서 운영한다.

| 구성 | 쓰는 서비스 | 무료 한도 | 하는 일 |
| --- | --- | --- | --- |
| AI | Gemini API 무료 등급 (Flash 계열) | 모델별 요청 한도, AI Studio에서 확인 | 질문 선정·교정, 녹음 듣고 발음 평가, 손글씨 사진 읽기, 단어 초안 |
| 사이트 호스팅 | Cloudflare (정적 사이트 + Workers) | 정적 파일 요청 무료·무제한, Workers 하루 10만 요청 | 사이트 제공, Gemini API 키를 숨긴 채 요청 전달 |
| 로그인·동기화·파일 | Supabase 무료 플랜 | DB 500MB, 파일 1GB | PC·휴대폰 동기화, 작문 사진·면접 녹음 보관 |
| 듣기 | 기기 내장 일본어 음성 | 무료 | 단어·예문·면접 질문 읽어주기 |

출처: [Gemini API 가격](https://ai.google.dev/gemini-api/docs/pricing), [Cloudflare Workers 가격](https://developers.cloudflare.com/workers/platform/pricing/), [Supabase 가격](https://supabase.com/pricing)

- **개인정보**: 무료 등급에서는 입력한 내용(답변, 녹음, 사진)이 Google 제품 개선에 쓰일 수 있다. 이름·연락처 같은 개인정보는 넣지 않는다.
- **API 키**: 브라우저 코드에 넣지 않고 Cloudflare Workers의 비밀값에 둔다. 내 계정으로 로그인한 요청만 전달한다.
- **한도 초과**: 그날은 AI 기능만 쉬고, 단어장·테스트·복습은 그대로 쓴다. 단어 초안·질문 선정은 가벼운 모델(Flash-Lite), 교정·발음·사진 분석은 Flash 모델로 나눠 한도를 아낀다. 모델 이름과 한도는 자주 바뀌므로 개발 시점에 다시 확인한다.
- **Supabase 일시 중지**: 무료 프로젝트는 1주일 동안 쓰지 않으면 일시 중지된다. 매일 공부하면 문제없고, 오래 쉬었다면 Supabase 화면에서 다시 켜야 한다. 설정의 ‘백업 내보내기’를 한 달에 한 번 한다.
- **용량**: 사진은 올리기 전에 1\~2MB로 줄이고, 녹음은 압축해 저장한다. 1GB가 차면 오래된 녹음부터 지울지 묻는다.
- **접속**: 휴대폰에서는 ‘홈 화면에 추가’로 앱처럼 쓴다. 녹음을 위해 첫 사용 때 마이크 권한을 허용한다.

**이전 안(Claude 아티팩트)과 비교**: 아티팩트 방식은 설치가 없고 Claude 구독으로 AI를 쓸 수 있지만, 녹음을 AI에 보낼 수 없고 Gemini도 연결할 수 없어 발음 평가가 불가능하다. 이번 안은 Cloudflare·Supabase 가입과 Gemini API 키 발급을 처음 한 번 해야 하지만, 발음 평가까지 모두 무료로 된다.

## AI 분석 가이드라인

AI 답은 그대로 믿지 않는다. 모든 AI 기능은 같은 공통 규칙으로 요청하고, 정해진 형식으로 받고, 사이트가 한 번 더 검사한 뒤 보여준다. 같은 규칙이 코드의 `public/ai-rules.js`에 있고, 모든 기능이 이 파일을 함께 쓴다.

### 공통 규칙 (모든 요청 맨 앞에 붙임)

1. 입력(녹음·사진·글)에 실제로 있는 것만 근거로 삼는다. 안 들리거나 안 보이는 것을 추측해 채우지 않는다.
2. 불확실한 부분은 표시하고, 확신도(높음·보통·낮음)를 함께 받는다.
3. 필드가 정해진 JSON 형식으로만 받는다. 형식이 깨지면 화면에 내보내지 않는다.
4. 설명은 한국어, 예시·교정 표현은 일본어(상용한자 기준)로 쓴다.
5. 지적은 중요한 것부터 최대 5개.
6. 칭찬이나 평가는 근거(어느 부분이 어땠는지)와 함께만 쓴다.

### 요청 방식

| 항목 | 규칙 |
| --- | --- |
| 결과 일관성 | 분석·교정은 무작위성 0(temperature 0)으로 같은 입력에 같은 답이 나오게 한다. 면접 질문 생성만 0.7 |
| 중복 실행 | 분석 중에는 버튼을 잠근다. 기다리는 동안 입력이 바뀌면 늦게 온 결과는 버린다 |
| 같은 입력 | 같은 녹음·사진·글은 저장된 결과를 다시 보여준다. ‘다시 분석’을 눌러야 새로 요청한다 |
| 형식 오류 | 한 번만 자동으로 다시 요청하고, 그래도 실패하면 다시 눌러 달라고 안내한다 |
| 모델 | 무료 등급 모델만 쓴다. 분석·교정·발음은 Flash, 질문 생성·단어 초안은 Flash-Lite |

### 기능별 기준

| 기능 | AI가 하는 일 | 지켜야 할 기준 | 사이트의 검사 |
| --- | --- | --- | --- |
| 발음 평가 | 녹음을 받아 적고 목표 문장과 비교 | 먼저 목표 문장 없이 들린 소리만 적고, 안 들리는 부분은 「？」. 지적 종류는 장음·촉음·ん·탁음/청음·요음·모음·억양·속도·누락·추가 중 하나 | 말소리가 없으면 다시 녹음 안내. 목표 문장과의 일치율을 직접 계산하고, 60% 미만이거나 다른 문장으로 인식되면 경고 |
| 면접 질문 | 상황·이력·지난 문답을 보고 다음 질문 1개 | 이미 한 질문은 다시 내지 않고, 앞 답변에 대한 꼬리 질문을 섞는다. 정중체 한 문장. 기출 질문이라고 단정하지 않는다 | 일본어 한 문장인지, 이전 질문과 거의 같지 않은지 |
| 면접 답변 분석 | 원문·해석·교정·다듬은 답변·발음 | 내 답의 경험·사실은 바꾸거나 지어내지 않고 표현만 고친다. 경어는 면접 수준(です・ます + 겸양어) 기준 | 다듬은 답변이 내 답보다 지나치게 길지 않은지(1.5배 이내) |
| 작문 글자 읽기 | 사진 속 손글씨를 텍스트로 | 내가 잘못 쓴 한자도 고치지 않고 그대로 옮긴다. 알아볼 수 없는 칸은 「？」, 원고지는 행·열 위치를 함께 | 읽은 글을 내가 먼저 확인·수정한 뒤에만 분석 |
| 한자 오류 | 잘못 쓴 한자 찾기 | ‘틀림’과 ‘판독 불확실’을 나눈다. 확실한 것만 빨간 표시, 불확실한 것은 회색 | 바른 글자가 상용한자인지 |
| 원고지 표기 | 규칙에 어긋난 위치 | 켜 둔 규칙만 검사하고, 규칙 이름과 행·열을 함께 | 행·열이 원고지 칸 수 안인지 |
| 단어 초안 | 후리가나·뜻·레벨·예문 | 후리가나는 히라가나만. JLPT 레벨은 추정이라고 표시 | 후리가나가 히라가나만으로 되어 있는지 |

### 점검 방법

- **일관성**: 같은 녹음으로 3번 분석해 결과가 같은지 본다.
- **시험용 입력**: 일부러 틀리게 읽은 녹음, 아무 말도 안 한 녹음, 다른 문장을 읽은 녹음을 저장해 두고, 각각 기대한 경고가 나오는지 본다. 작문·면접도 같은 방식으로 시험용 입력을 두고, AI 요청 문구를 고칠 때마다 다시 돌려 본다.
- **녹음 연동**: 휴대폰에서 녹음한 파일이 PC 목록에 바로 나타나고, PC에서 재생·분석되는지 본다. 반대 방향도 똑같이 확인한다.

### 기기 간 동기화

화면에 보이는 것 중 기기마다 달라야 하는 것을 뺀 **모든 것이 동기화 대상**이다. 저장은 항상 서버(Supabase)에 하고, 브라우저에는 연결이 끊겼을 때를 위한 임시 사본만 둔다. 점검 페이지에서 발음 분석 결과가 다른 기기에 보이지 않았던 것처럼, 결과를 브라우저에만 두는 일은 없게 한다.

| 대상 | 예 | 동기화 방법 |
| --- | --- | --- |
| 학습 데이터 | 단어, 한자 훈음·메모·링크, 문법, 상황 프리셋 | 저장 즉시 DB에 기록 |
| AI 분석 결과 | 발음 분석, 면접 문답 분석·교정, 작문 글자 읽기·교정, 단어 초안 | 결과를 DB에 저장하고 입력(녹음·사진·글)과 연결. 같은 입력은 어느 기기에서든 저장된 결과를 보여주고 다시 분석하지 않는다 |
| 파일 | 녹음, 작문 사진, Gemini 음성 | 보관함(Storage)에 올리고 DB에 목록 행을 남김 |
| 진행 중인 작업 | 단어 테스트(판·남은 더미·경과 시간), 면접 세션, 작문 작성, 입력하던 글 | 카드를 넘길 때·문답이 끝날 때·입력을 멈춘 뒤 몇 초마다 저장. 휴대폰에서 시작해 PC에서 이어서 한다 |
| 학습 기록 | 아름/모름, 자주 틀리는 한자·문법, 발음 주의 단어 | DB에 기록, 통계는 기록에서 계산 |
| 설정 | 보기 형식, 가리기 기본값, Gemini 음성·속도, 고른 모델, 원고지 검사 항목 | DB의 설정 행 하나에 저장 |
| 동기화하지 않는 것 | 기기 내장 음성 선택, 마이크 권한, 화면 크기에 따른 배치 | 기기마다 다르므로 그 기기에만 저장 |

- **실시간 반영**: 다른 기기에서 바뀐 내용은 새로고침 없이 바로 화면에 나타난다.
- **동시 수정**: 두 기기에서 같은 항목을 고치면 나중에 저장한 쪽이 남는다. 단, 작문·답변 원고 같은 긴 글은 덮어쓰기 전에 ‘다른 기기에서 바뀜’ 알림을 띄우고 고르게 한다.
- **오프라인**: 연결이 끊기면 기기에 임시로 모아 두었다가 다시 연결되면 올린다. 화면 위쪽에 ‘저장 대기 중’ 표시.
- **개발 점검**: 기능을 만들 때마다 ‘다른 기기에서 열면 그대로 보이는가, 이어서 할 수 있는가’를 확인한다.

**한자 데이터 출처**: 부수·획수·음독·훈독·이체자는 [KANJIDIC2](https://www.edrdg.org/wiki/KANJIDIC_Project.html)(CC BY-SA 4.0), 획순은 [KanjiVG](https://kanjivg.tagaini.net/)(CC BY-SA 3.0)에서 가져와 사이트에 넣고, 설정 화면에 두 출처를 표시한다. 내가 등록한 단어에 나오는 한자부터 채운다. 한국어 훈음과 구성 메모는 내가 입력하고, AI 초안을 쓸 때도 네이버·nihongokanji 링크로 확인한 뒤 저장한다.

## 개발 방식과 학습 플랜

개발은 단계를 나누지 않고 **처음부터 모든 기능을 한 번에** 만든다. 대신 Nov 14, 2026 면접까지는 아래 학습 플랜에 맞춰 사이트를 쓴다.

- **한 번에 전체 개발**: 단어장·테스트·한자 정보·검색·문법·면접·작문을 Claude Code에서 처음부터 함께 만든다. 화면 부품과 데이터 구조를 처음부터 맞춰 두면 나중에 고칠 일이 적다.
- **개발 전 점검 (10/21 완료)**: 0단계 점검 페이지로 PC·휴대폰 동기화(메모·녹음 파일), 듣기, 녹음, Gemini 녹음 분석(같은 녹음을 여러 번 분석해도 같은 결과인지 포함)이 되는지 먼저 확인한다. 녹음이나 무료 한도에서 막히면 면접 기능 설계를 바꿔야 하기 때문이다.
- **완성 전에도 공부는 시작**: 사이트가 완성되기 전에는 1구간의 답변 원고를 메모로 쓰고, 완성되면 면접·단어장으로 옮겨 교정을 받는다.
